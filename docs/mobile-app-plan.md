# 手机 App 迁移计划

## 目标

将现有“华理宿舍电量查询”微信小程序迁移为 Android App。继续复用 `https://power.ecust.cc` 和现有 Node.js 查询服务，不依赖微信审核、微信登录或订阅消息。

## 技术路线

- 客户端：Expo React Native + TypeScript，生成 Android 原生工程并使用 Android Studio 调试。
- 服务端：保留现有 Express、SQLite、定时采样和电量查询逻辑。
- API：继续使用 `/api/buildings`、`/api/query`；后续为独立 App 增加设备身份和推送接口。
- 本地状态：保存每个校区上次选择的楼栋和寝室，启动时恢复最近一次查询。
- 发布顺序：先交付可安装的查询 MVP，再接入“我的寝室”、趋势和系统通知。

## 功能映射

| 小程序能力 | App 方案 | 阶段 |
| --- | --- | --- |
| 奉贤/徐汇切换 | 原生分段选择器 | MVP |
| 楼栋与寝室查询 | 复用现有公共 API | MVP |
| 上次寝室自动恢复 | App 本地安全存储 | MVP |
| 设为“我的寝室” | App 匿名设备身份 + Bearer Session | 第二阶段 |
| 历史趋势 | 复用现有采样和 `/api/history` | 第二阶段 |
| 低电量提醒 | Expo Push / FCM / APNs，替代微信订阅消息 | 第三阶段 |
| 微信登录 | 不移植；改为 App 设备身份，后续可选账号登录 | 第二阶段 |

## 实施阶段

### 第一阶段：查询 MVP

1. 在 `mobile/` 新建 Expo React Native TypeScript 工程。
2. 移植校园切换、楼栋加载、寝室输入、查询和结果卡片。
3. 为奉贤、徐汇分别保存上次楼栋和寝室，避免切换校区后回到默认项。
4. 处理加载、空数据、请求失败、超时和服务端错误。
5. 完成 TypeScript 检查，并在 Android 模拟器或真机运行。

验收标准：安装后无需微信即可查询；重启 App 会恢复最近选择；切换校区不会丢失各校区选择。

### 第二阶段：我的寝室与趋势

1. 新增 App 匿名注册接口，由服务端生成不可猜测的设备身份和会话令牌。
2. 将服务层参数从微信语义的 `openid` 抽象为通用 `ownerId`，兼容已有小程序数据。
3. App 安全保存会话令牌，并接入 `/api/watch` 与 `/api/history`。
4. 移植阈值设置、取消“我的寝室”和折线趋势图。
5. 增加会话失效、换机和清除数据后的恢复策略。

验收标准：同一安装实例只能看到自己的关注寝室；取消关注后按现有规则清理最后一个关注者对应的历史。

### 第三阶段：低电量系统通知

1. App 获取 Expo Push Token，并经鉴权接口登记设备。
2. 服务端保存推送令牌、平台和启用状态。
3. 将当前微信模板消息发送器抽象为通知提供方，同时保留或移除微信实现。
4. 用户自行设置阈值；低于阈值时发送一次通知，电量恢复后允许下一次提醒。
5. 处理通知权限拒绝、令牌轮换、失效令牌和重复发送。

验收标准：Android 真机在后台可收到一次性低电量提醒，提醒阈值始终使用用户设置值。

### 第四阶段：构建与发布

1. 配置 App 图标、启动图、包名和版本号。
2. 使用 Android Studio 或 EAS Build 生成 Android AAB/APK。
3. 完成隐私说明、网络权限、通知权限和数据删除说明。
4. 做弱网、冷启动、跨校区、会话过期、后台通知和升级回归测试。

## 不在 MVP 中伪实现的内容

- 不在普通网页或 App 中调用 `wx.login`。
- 不展示无法工作的“订阅一次提醒”按钮。
- 不把微信 OpenID 当成独立 App 的账号系统。
- 不在客户端保存微信 AppSecret 或任何服务端密钥。

## 风险与约束

- iOS 正式发布需要 Apple Developer 账号和 macOS/EAS 云构建环境。
- Android 上架不同商店的签名、备案和隐私材料要求不同。
- 系统推送需要额外服务端配置；仅完成查询 MVP 不会自动获得后台提醒能力。
- 当前生产 API 应继续限流，App 身份接口还需要防滥用和令牌撤销测试。
